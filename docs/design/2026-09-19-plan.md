# Rewrite implementation plan

Companion to `2026-09-19-rewrite.md` (the design). This is the working plan for the
`claude/rewrite` branch. Each stage ends with a gate: subagent reviews with named
charges, all blockers fixed, hardware tests green on the maintainer's PC, before the
next stage begins.

## Conventions

- Branch `claude/rewrite`, one PR to `main` at the end. Conventional commits, author
  Lavindeep Dhillon, explicit `git add` paths.
- .NET 10 SDK, portable install at `C:\Users\lavin\Documents\Codex\tools\dotnet`
  (added to PATH per shell, never machine-wide).
- Test command: `dotnet test -c Release`. Hardware tests run only when `APEX_HW_TESTS=1`
  and are marked with a `[HardwareFact]` attribute that skips otherwise.
- Nothing in the hook callback, sensor loop, or engine tick allocates. A test asserts
  zero allocations across 10,000 engine ticks with `GC.GetAllocatedBytesForCurrentThread`.
- Every stage's review findings are recorded in `docs/design/reviews/stage-N.md` with
  the outcome per finding (fixed, rejected with reason, deferred with stage).

## Gate protocol

At the end of each stage, dispatch reviewers in parallel, each with the design, the
plan, and the diff for the stage:

1. Trace reviewer: walks every design requirement in the stage's scope and points to
   the code and test that satisfy it, or flags the gap.
2. Failure reviewer: enumerates every thread, lock, handle, and failure path in the
   stage's code and looks for races, leaks, deadlocks, and silent swallows.
3. Test reviewer: reads the tests and names the behaviours they do not pin.
4. Stage-specific reviewer where the plan names one below.

Blockers and highs are fixed before the stage closes. Mediums are fixed or recorded
with a reason. The stage closes with all tests green, hardware tests included.

## Stage 0: measurement spike

Goal: numbers before design freezes. A throwaway console program at `spike/Spike`,
committed so the history keeps it, deleted in stage 1.

Setup:

- Install the .NET 10 SDK into the portable directory with `dotnet-install.ps1`.
- `spike/Spike.csproj` on `net10.0-windows`, references HidSharp and
  Nefarius.ViGEm.Client. No tests, no abstractions.

Subcommands, each writing a CSV under `spike/out/` and printing a summary:

| Command | What it does | Output |
| --- | --- | --- |
| `probe` | Enumerates HID devices with VID 0x1038, prints product id, usage page and usage per interface, report lengths, container id. Opens the 0xFFC0 interface, sends 0x90, prints the firmware string. | Device table, firmware. |
| `cycle --seconds 30` | Polls groups 2 and 3 back to back with the queue drained before each write. Records per-exchange latency and per-cycle period. | p50, p99, max for exchange and cycle; fault count. Run twice: with SteelSeries GG running and with it stopped (`Stop-Process SteelSeriesGG`, restarted afterwards). |
| `step --seconds 20` | Polls group 2 at maximum rate while the user taps W as fast as possible. Logs raw and filtered W with timestamps. | 10 to 90 percent rise time of raw and filtered per press, and the lag of filtered behind raw. |
| `tick --seconds 10` | Runs a 1 ms loop three ways: `Thread.Sleep(1)`, `WaitHandle.WaitOne(1)`, and a `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` timer. | Tick period histogram per method: p50, p99, max. |
| `e2e --seconds 30` | Connects a ViGEm pad. Installs a WH_KEYBOARD_LL hook that timestamps W down (not swallowing). Polls group 2 and writes W depth to the right trigger. A second thread samples `XInputGetState` at 1 kHz. | For each press: hook timestamp to first non-zero trigger readback, and sensor-crossing-threshold timestamp to readback. p50, p99. |
| `rest --minutes 10` | Polls groups 2 and 3 with all keys released. | Per key: mean, peak-to-peak, min, max, and drift of a 5 s moving mean from first to last, in counts. |
| `travel` | Prompts: release W, press W fully, then press W slowly until the digital key-down arrives (Raw Input). | Rest count, full-press count, span, and the count at which GG's digital actuation fires, for W, A, S, D. |
| `kill` | Parent spawns itself as a child with `--child`. Child connects a pad, sets right trigger 255, installs a swallowing hook on W, signals ready, blocks. Parent waits 1 s, calls `TerminateProcess`, then polls `XInputGetState` every 10 ms for 3 s and sends a synthetic W with `SendInput` to a message window. | Time from kill to "no controller", and whether the synthetic W arrived. |

Deliverable: `docs/design/measurements.md` with every number and the four decisions
they settle:

1. Raw or filtered bytes for depth.
2. Freshness rule constants and the sensor loop pacing (back to back, or a floor).
3. Engine timer method and the achievable tick period.
4. Whether in-process ViGEm with process death is safe as designed.

Plus the response representation for the profile model: fit the shipped racing curves
against an exponent-plus-saturation model and record the error. If under 3 percent,
adopt exponent plus saturation and drop point lists.

Gate: one Opus reviewer checks the measurement method and the conclusions drawn.

## Stage 3: output and session

| File | Responsibility | Tests |
| --- | --- | --- |
| `Output/ViGEmPad.cs` | Connect with the neutral readback loop, `Submit(in PadReport)` when changed and at most every 2 ms, `Zero`, `Disconnect` (zero first, idempotent). Driver exceptions surface as `PadFault`. | Fake client: submit only on change; zero before disconnect. Hardware: connect reads all-zero; full-scale round trip via XInput. |
| `Output/DriverStatus.cs` | Present and running, present but not started, missing. Via the ViGEm client probe plus the service state. | Hardware: reports running on this PC. |
| `Session/Session.cs` | The state machine from the design table. Owns the four threads' lifecycle. Every event in the table is a method; every outcome is observable. | Fakes for all inputs: one test per row of the design table, plus ordering tests (stop during start, unplug during alt-tab). |
| `Session/Watchdog.cs` | Runs in the hook thread's timer: engine tick timestamp older than 200 ms zeros and unplugs the pad and unhooks. | Fake clock: fires once; does not fire while ticking. |
| `Session/CrashGuard.cs` | `AppDomain.UnhandledException` and unobserved task handlers: zero, unplug, unhook. | Hardware: kill test and wedge test below. |
| `Session/EngineLoop.cs` | Engine thread: timer, drain ring into store, apply hook state, apply snapshot through `SourceSelector`, `Mapper.Tick`, submit, publish tick timestamp. | Zero allocations; hardware loopback test. |

Hardware tests, each a `[HardwareFact]`:

- Loopback: synthetic depth ramp into the engine, XInput sampled at 1 kHz from another
  thread; asserts at least 200 distinct trigger values per second and p99 submit-to-
  readback under 4 ms.
- Kill: child harness (pad connected, trigger 255, hook swallowing W) terminated by the
  test; asserts XInput reports no controller within 1 s and a synthetic W reaches a
  test window.
- Wedge: child harness blocks its engine thread; asserts the watchdog zeros within
  300 ms and unplugs.
- Soak: 30 minutes of synthetic input; asserts working set flat within 10 MB, handle
  count flat, no key left non-zero at the end, no GC pause over 5 ms. Run once per
  gate, not on every test run.

Gate reviewers: trace, failure, test. Extra: safety reviewer who attacks the
"what the game sees" column of the session table.
